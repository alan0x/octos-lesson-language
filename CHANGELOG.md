# Changelog

## Unreleased

### Added

- Number line (decision 0013), the first card of a subject plugin: kind `number_line` in `plugin-math` (math plugin 0.2.0).
  - Content: a range and ticks (major step and subdivisions; labels as integers, decimals, or stacked fractions such as 3/4, which are not reduced, or mixed numbers; decimals keep the places the step needs, so quarters read 0.25 and 0.75; when labels would overlap they thin out on a regular stride, 0 keeps its label, and every tick stays); points at numbers or exact fractions (`"3/4"`, `"1 1/2"`), closed or open, optionally shown only when emphasized; jumps from a point or a value, drawn as an arc or one hop per smallest tick, whose end the program computes; and intervals with open, closed or unbounded ends.
  - Points, jumps and intervals are addressable parts, and their values can be bound to lesson variables and animated.
  - A learner can drag a point (`interaction: {kind: "drag", variable}`, control `number_line_point`). It snaps to the smallest tick, and `expression_target` judges it. A drag task whose target lies between ticks is rejected as unreachable.
  - First-party plugins ship with OLL and are installed by default (`FIRST_PARTY_EXTENSIONS`; `firstParty: false` leaves them out). A number line requires `plugin:math/number-line@1` and the math plugin 0.2.0, not a core node feature, so a player without it refuses the lesson before playback. Lessons without a number line need no plugin and derive the same requirements as before.
  - `buildNumberLine` builds the card for Coach and Studio. The example `learner-context-number-line-v2` ("3 + (−5)") replaces the seven boxes that faked a number line with the real card; its move is five hops from 3 to −2. Teaching observation: `npm run teaching:observe:number-line`.

- `plugin-physics` adds `buildConstantSpeedMotion` (subject plan P2, step 3). It draws an object moving at constant speed along a track (s = v·t), linked to its distance–time graph: a line through the origin whose slope is the speed. Time and speed can each be a lesson variable. Dragging time moves the object, its distance readout and the graph's point together; changing speed changes the line's slope. It uses only shared geometry and plot features, so it needs no new player feature. `niceAxisMax` rounds the track length and the graph's distance axis up to 1, 2, 2.5 or 5 times a power of ten. Authoring helpers only.

- Subject plugins `plugin-chemistry`, `plugin-biology` and `plugin-earth-space` (decision 0012, decision S12 of the subject plan): manifest (depends on `shared`) and Jev subject line in Chinese and English, with no recipes yet, so the Jev subject question can offer them (P2). `plugin-subjects` lists all five subject plugins (`SUBJECT_PLUGINS`) and returns a plugin's subject line by ID and language (`subjectDescription`). It also builds the Jev subject question (`subjectQuestion`: subject lines plus `none` and `unclear`) and selects plugins from Jev's probabilities (`selectSubjectPlugins`, thresholds `SUBJECT_THRESHOLDS` T1 0.6 / T2 0.05), so hosts and evaluation scripts share one definition. Authoring metadata only.

- Plugin extension point for execution features (decision 0012). A host passes installed `ExecutionExtension`s (plugin id and version, namespaced features `plugin:<id>/<name>@<major>` each mapped to the plugin version that introduced it, and an optional `detect` over node content). `composeExecutionFeatures` joins them to the core table and rejects foreign, duplicate or too-new features. `deriveExecutionRequirements`, `assertExecutionSupported`, `assertExecutionDeclaration` and `compilePlaybackOperations` (`executionExtensions`) take them as an option; plugin features add `requiredPlugins` instead of raising the player version. `assertDeclarationPlayable` checks a package's declared requirements before playback and names a missing or outdated plugin. No plugin features exist yet; lessons without them derive exactly the same requirements.

- `plugin-math` adds the rest of Coach's math recipes as builders: `buildCircleAndArc`, `buildCoordinateCircle`, `buildUnitSquareArray`, `buildCircleAreaRearrangement`, `buildGeometricRearrangement` (with the rearrangement constructions and their facts), `buildCubeWithSection`, `buildFunctionSurface` and `buildImplicitSurface` (with `implicitSurfaceDomain` and `buildImplicitSurfaceObject`). Callers resolve their own numbers and pass a translator for the Chinese source labels. Authoring helpers only.

- Subject plugin `octos-lesson-language/plugin-physics` (decision 0012, shared layer): manifest (depends on `shared`), Jev subject line, and `buildSpringAndMass`, a mass on a spring (x = cos phase) linked to its displacement graph. Authoring helpers only.

- `plugin-math` adds 3D solids, moved from Octos Learn's Studio: the `Solid` shape model (box, cylinder, cone, regular or custom-base prism and pyramid, truncated pyramid, frustum, sphere, hemisphere, ellipsoid, torus, regular polyhedra, stacked composites), its helpers (`solidZRange`, `solidUnfolds`, `baseCorners`, `compositeHeight`, `solidObjects`, `boxFaces`), `describeSolid` (zh/en) and `buildSolid` (a scene with an optional sliding cut plane, a net that unfolds, highlightable box faces and stable face targets). Authoring helpers only.

- Subject plugin `octos-lesson-language/plugin-shared` (decision 0012, shared layer): `buildProcessDiagram` and `processDiagramContent`, a diagram of steps as a chain or as a cycle back to the first step, with stable step and edge names (`step-01`, `edge-01`, `edge-close`). `plugin-math` adds `buildFunctionPlot`: curve names (`primary-curve`, `curve-02`, …), sample points whose y follows the primary curve (two make a secant), and fixed-x slope references. Authoring helpers only.

- Subject plugin `octos-lesson-language/plugin-math` (decision 0012, shared layer): the math plugin's manifest, its Jev subject line, and recipe builders that turn neutral input (recipe parameters, number expressions, caller-supplied text) into OLL authoring actions with stable part names. First builders: `buildUnitCircle` (unit circle with a draggable angle, optionally linked and grouped with its sin or cos graph) and `buildCirclePolygons` (regular polygons in a circle: inscribed, or inscribed and circumscribed as bounds on π). Coach and Studio are meant to call these instead of each writing the geometry. Authoring helpers only; no lesson contract or player change.

- Ink runtime: `replaceSelectionWithAiPaths(artifactId, paths, expected, color?)` replaces the selected strokes with AI paths in one undoable command. It refuses (`INK_INVALID_RECORD`) unless the document, the selected stroke IDs and the selection and content revisions still match the captured `expected` snapshot. One undo restores the original strokes; the artifact ID is consumed like `writeAiPaths`. Runtime API only; no lesson contract change.

- Opt in to stable face targets on a solid with `face_targets: true` (player 0.10.0, `scene3d:face-targets`). Use `<scene>#<object>-<surface>-face` to mark a face. A latent box highlight at the four corners of a single opted-in face follows that face as it unfolds.

- More 3D solids: `prism` and `pyramid` (3–12 sides), `frustum` (bottom and top radius), `hemisphere`, `torus` (ring and tube radius), and the regular polyhedra `tetrahedron`, `octahedron`, `dodecahedron`, `icosahedron`. Drawn from shaded facets like the cylinder, cone and sphere (flat faces keep their edges), and cut into cross-sections from the same facets. Capability `scene3d:more-solids`, player 0.9.0. Web runtime exports `solidFacets`.
- Prisms and pyramids on any convex base: `base` (3–12 `{x, y}` corners, centred on its centroid) instead of `sides` + `radius`. A pyramid with `top_scale` (0 ≤ k < 1) is truncated (a frustum of a pyramid). New solid `ellipsoid` with `radii: {x, y, z}`. Capability `scene3d:more-solids`.
- Nets: `unfold` (0–1) on `box`, `prism`, `pyramid`, `cylinder` and `cone` opens the solid into its net (sides swing about their base edges; a cylinder's side unrolls into a 2πr rectangle, a cone's into a sector of the slant height). Faces keep their size, so the net's area is the surface area. Bindable (`<as>.unfold`, held to 0–1), so a slider opens the box. Capability `scene3d:unfold`, player 0.9.0.
- Stacked solids: a face two solids of one scene share, facing opposite ways (a cone standing on a cylinder, a roof on a box), is inside the composite and is drawn as its edge (the seam) only. A cone's net stands upright as it opens, like a cylinder's; a fully opened round side is one rectangle or sector.
- Diagrams of steps and cycles read in one direction: a chain of boxes (steps) and a ring of 3–8 boxes (a cycle, every box one arrow in and one out; not geometry points) draw their edges as arrows from box edge to box edge; a cycle is laid out on a ring, first box at the top, clockwise, and its card keeps the ring's proportions. Rendering only; no contract change.
- A card can grow where the learner writes (decision 0011): `place.relation: "continues"` with `offset: {x, y}` (board units from the anchor's top-left, as drawn) attaches learner ink or math to an earlier card; the anchor and its continuations lay out as one block with one frame (`BoardLayout.blocks`). A math continuation, or neat math that replaces one, with `align: "equals"` lines its "=" up with the nearest math above it in the block (the web runtime measures each math card's "=" and passes `equalsX` to the layout). Continuations of a hidden card move to its replacement, to what it continued, or into its place. Capability `placement:continues`, player 0.9.0.
- Learner ink takes `drawn_size: {width, height}`: shown at the size it was written (scaled down past 1200 wide) instead of in a fixed 340×230 card. Capability `ink:drawn-size`, player 0.9.0.
- Beats take `pace: "continuous"`: the beat follows straight on from the one before (the next sentence of the same speech). Playback marks its operations, and the end of the beat before it, `continues`; the web runtime plays them without the pauses that separate teaching beats (250 ms between the sentences instead of about 1.4 s). Capability `beat-pace:continuous`, player 0.8.0.
- A learner-taught beat may be words alone (`say` with no actions); other beats still need an action.
- Learner ink can appear stroke by stroke as it was written: `write kind: "ink"` takes `shown_strokes` (the first N strokes in drawing order); a `revise` of the same snapshot with a larger `shown_strokes` shows more, and the web runtime draws only the newly shown strokes. Revising ink keeps its placement (an annotation stays on its card). Capability `ink:shown-strokes`, player execution version 0.8.0.
- Ink runtime: each stroke records when it was drawn (`data-octos-ink-drawn-at`, kept by partly erased pieces; strokes restored from a saved document are not re-timed). Selection snapshots number their strokes (`<g data-oll-stroke="i">`, one group per stroke even when js-draw draws it as several paths) and report `component_drawn_at` (outside the checksum) when every stroke was timed. The web runtime keeps the stroke numbers through sanitizing and exports `inkStrokeGroups` and `limitInkStrokes`.
- Lesson variables accept `wrap: true` (min and max are the same place, e.g. an angle over one full turn); `animate` on such a variable takes the shorter way round. Capability `variables:wrap`, player 0.7.0 (decision 0010). Web runtime exports `animatedVariableValue`.
- `emphasis: "none"` ends an earlier emphasis of the same target (node or fragment) without drawing attention (no camera move). Capability `emphasis:none`, player execution version 0.7.0 (decision 0009).
- Numeric answer tasks (`completion.kind: "numeric_answer"`, `allowed_operations: [{"kind": "answer_entry"}]`, `student-tasks:numeric_answer`, player 0.5.0): the learner types a whole number, decimal, fraction or mixed number, checked exactly (or within `tolerance`), optionally in simplest form. The task carries an `anchor` board card, normalized to its Canonical node ID. Core exports `parseNumericAnswer`, `checkNumericAnswer` and `isSimplestFraction`.
- Web session `submitStudentAnswer(taskId, text, input)`: records an `answer_submit` student operation and judges the open numeric answer task; text that is not a number returns `{ unreadable: true }` and is not an attempt. Attempts of numeric answer tasks keep the typed `answer`, and restored progress must repeat its own check.
- Point bindings (plot and geometry x/y) accept `hide_when_undefined: true`: when the expression has no finite value (e.g. the intersection of parallel lines) the point is hidden instead of failing the lesson, and it returns once defined (`binding-hide-undefined`, player 0.3.0).
- `lesson.reflections` (Authoring schema, validator, Canonical normalization, `reflections` execution capability, player version 0.3.0): thinking questions whose reference answer opens after the lesson in a collapsed card under the anchoring board card. The web session exposes `reflections`, and teaching layout places `reflection` attachments under their anchor.

### Fixed

- Cards are drawn at the size the layout gives them. Their padding and border were added outside that size (content-box sizing), so every card except math was 38px wider and about 34px taller than laid out: cards crossed their group frames and the gaps between cards shrank. Visual cards now scale their drawing to the slightly smaller inner width, and text wraps to the card the layout planned. Rendering only.
- Geometry cards show their axis labels again. The zoomable view replaced each axis with its range, which dropped the label, so every geometry card showed "x" and "y". Rendering only.
- 3D highlights accept `shown: "when_emphasized"`: the part is filled only once emphasized; while a latent face faces the viewer its label shows and it can be pointed at.
- 3D boxes draw the faces turned away from the viewer as dashed hidden edges, so a see-through box no longer reads two ways (near faces seen as far). Capability `scene3d:latent-highlights`, player 0.7.0.
- 3D cards: the scene fills the space its card's title leaves instead of assuming a 24px title, so a titled 3D card no longer runs 8px past its bottom (reported as content overflowing the card).
- Math cards are sized to their rendered formula (up to 680 px) as intended: the measurement looked for `.katex-html > .katex-base`, which KaTeX never produces (its class is `base`), so every math card kept its length estimate (at least 280 px) and longer one-line formulas wrapped.
- Teaching layout: a card that replaced another (Neat math over the learner's handwriting) keeps the replaced card's turn and section, so it stays where the handwriting was instead of moving below handwriting written after it. `visibleBoard` marks the replacement with `in_place_of`.
- Teaching camera: when a composed frame cannot be readable at the host floor, cards and controls the current Beat is not about are dropped first (oldest first), so a long variable demonstration on an earlier card no longer leaves only that card's slider in the frame while the Beat's new card stays off screen.
- Teaching camera: floating UI (occlusions) only narrows the safe area when the content, fitted and centred in the whole area, would actually overlap it (with 8px clearance). `focusWorldRect(rect, { parts })` / `planFocusCamera(..., parts)` let the host list the cards inside the rect, so a small corner avatar beside an empty corner of the course no longer shifts the course-end overview sideways.
- Teaching layout: controls shared by several visuals dock under the first of them at its width (8 units below), like a single visual's controls; practice stays beside them, below any visual above it.
- Board view: a card's measured size is reused while its content signature and width are unchanged, so a variable change re-measures only the visuals it drives instead of forcing a browser layout per card on every animation frame.
- Teaching layout: a single visual's variable controls dock directly under it at its width instead of forming a column on its left, so they cost no row width; practice still opens left of the visual after the lesson.
- Teaching camera: the lenient "inside the composed frame" hold applies only within one Beat; a new Beat whose subject sits inside a wider earlier frame is re-framed when it can be shown clearly larger.
- Teaching layout: a card that no longer fits to the right of its row continues under an earlier column of the same band when that column has room, and a short step (at most two cards) continues under the previous step's column instead of opening a column at the far end of the row.

- Teaching camera (web-runtime): every automatic request composes the Beat's own targets (declared focus plus the cards the Beat writes) and, while readable, the cards the Step wrote earlier; a request is held when its scene is already visible, near the planned scale and centred (subsets of the composed frame are always held), so pointers and focus boundaries no longer slide the board back and forth. Hosts can cap automatic zoom with `setAutomaticCameraMaximumScale()` and pass Step context through `setBeatTargets(targets, stepContext)`; the session exposes `stepContextTargets`.
- Teaching layout: `composition.readingScale` sizes rows and columns for the scale the host camera reads them at (default 0.9); non-math cards keep their natural width as layout input, so a card stretched to its column no longer jumps to a new band when a later card widens that column.
- A note's supporting visual joins its camera frame only while both stay readable; course framing uses the same centred near-fit choice as teaching.

- Align the Authoring Schema action payload requirements with the reference validator. In particular, `connect` now declares its stable local alias as required.
- Document reference types and the required Session resource-to-local-fragment mapping in the model Authoring contract.
- Align `close.focus` with the validator: it is a non-empty list of existing visual-object aliases, not free-form summary text.
- Allow focus actions and lesson-close focus to target visible connections; connections remain invalid as layout anchors or group members.
