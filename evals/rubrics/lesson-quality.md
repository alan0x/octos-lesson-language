# OLL Lesson 质量评分

每个维度 0–4 分，协议质量与教学质量分开报告。

## A. 协议质量

1. 可解析性：是否为完整 JSON；
2. Schema：是否满足 Authoring Schema；
3. 语义引用：别名、fragment、anchor 和成员是否有效；
4. 完整性：Lesson、Step、Beat 和 close 是否完整；
5. 可规范化性：能否无修复转换为 Canonical Events。

## B. 教学质量

1. 学科正确性；
2. 请求覆盖；
3. 渐进性；
4. 讲述与板书一致性；
5. 白板利用质量；
6. 一轮连续完成；
7. 个性化是否引用真实 Context；
8. 是否产生无证据的学生判断。

### 评分锚点

每个维度统一使用：

- `4`：完整、准确，证据明确，没有实质问题；
- `3`：总体合格，有轻微遗漏或表达问题，但不妨碍学习目标；
- `2`：部分合格，存在会明显降低理解或迁移的问题；
- `1`：严重不足，只触及目标的一小部分或包含重大混乱；
- `0`：缺失、相反，或存在足以误导学生的致命错误。

质量门禁由宿主计算，不采用 judge 自报结论：总分至少 24/32，且学科正确性、请求覆盖、渐进性、讲板一致性均不低于 3，同时不能存在 `major` 或 `fatal` critical error。

Context 维度的无上下文场景不记零分：没有 Learner Context 时，不编造个性化和学生掌握判断即可获得高分。评分必须给出 OLL 中可定位的简短证据，不允许只写主观形容词。

## 首次实验记录

- 保留原始模型输出；
- 不做自动 JSON 修复；
- 同时记录 first-pass 和一次明确重试结果；
- 记录模型、provider、参数、Skill commit、Schema commit；
- 人工评分者必须能看到学生请求和全部 Context。
