# 0004：交互语义白板 MVP 的状态与仓库边界

状态：Accepted
日期：2026-08-12

## 决定

课程变量是动画、拖动、任务和跨视图联动的唯一共享状态。OLL Core 定义并验证变量与安全关系；Web Runtime 负责把状态变化呈现为动画或直接交互。不得让 Geometry、Plot 或 3D 各自保存一份同名变量。

OLL 的可复用 Runtime 继续留在 OLL Git 仓库。`octos-web` 通过版本化依赖使用它，只提供产品宿主。笔迹浏览器适配以后以 OLL 仓库的可选包加入，并按需加载；它不进入 headless Core。

Canonical OLL 与学生原始笔迹分开保存。任何识别、纠错或增强都是旁路结果，通过稳定来源引用关联，不能覆盖原输入。

MVP 不实现通用插件系统。后续学科组件只能通过受控、版本化、宿主批准的组件注册表加入，Lesson 不能下载或执行任意代码。

## 原因

一份共享变量状态可以让同一教学关系同时驱动 Geometry、Plot、读数和以后加入的 3D，也能被 headless 测试验证。把 Runtime 留在语言仓库可以让规范、Reducer、浏览器实现和 conformance fixture 同版本演进，避免产品仓库出现第二套解释器。分开保存学生原稿则保证系统理解错误时仍可恢复和审计。

## 后果

- 第一个实施切片必须先完成变量、受限表达式和状态恢复，不能直接从动画 UI 开始。
- 所有变量表达式必须通过白名单解析器，不允许 `eval`、`Function` 或脚本扩展。
- 笔迹库、3D 引擎和未来学科组件是 Runtime 依赖选择，不成为 OLL 文本中的可执行代码。
- 新能力必须带不支持时的明确降级和同仓库测试证据。
