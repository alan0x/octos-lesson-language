# 0024：数轴卡片自己的缩放

状态：Accepted（产品负责人 2026-11-25 确认设计和下面三个问题）
日期：2026-11-25
草图：交接目录 `handoff-math-expressiveness/runs/number-line-zoom/sketch/index.html`（BT-19、BT-20 两张卡片，今天的截图和可以点的提议版本；提议版本由草图自己的绘制代码画，不是 OLL 的）

## 背景

- **产品负责人（2026-11-25，看完第 3 次客观检查的课）**：数轴的刻度常常太挤，看不清；应该能用滚轮或缩放按钮放大。
- **两个例子**（卡片约 370 像素宽）：
  - BT-19（47 页再读 10 页）：0 到 70，每个整数一个刻度，刻度之间不到 5 像素，像一把梳子。
  - BT-20（把 347 四舍五入到十位）：300 到 410，共 110 个刻度；340、345、347、350 四个点挤在一起，互相压住。
- **画板已经能缩放，但解决不了这个问题。**
  - 画板的缩放是光学的：滚轮（在数轴上也一样）和双指都把整个画面放大，最多 2.2 倍。
  - 点、字和刻度一起变大，所以挤在一起的点放大后还是挤在一起。2.2 倍时 345、347、350 仍然互相压住（截图在第 3 次检查的记录里）。
- **窗口是程序选的，不是模型选的。**
  - Coach 的数轴适配（`number-line-fit.ts`）在放得下时总从 0 开始。
  - 一个窗口最多 58 个计数单位（`MAX_WINDOW`），每个单位画一个刻度。
  - 所以 BT-19 的梳子是现在的设计本身造成的。

## 提议

1. **数轴卡片有自己的缩放：放大的是数，不是字。**
   - 放大以后，数轴显示整条线的一段，数与数之间拉开。
   - 字号、点的大小、线宽都不变。
   - 所有数轴配方都有：`number_line`、`number_line_compare`、`number_line_solution`、`number_line_rounding`、`number_line_steps`。
2. **控件。**
   - 卡片右上角三个按钮：「−」「+」「整条」。按钮以卡片上标出的点为中心缩放。
   - 滚轮的规则：**指针在数轴卡片上时，滚轮缩放数轴；在卡片外，滚轮照旧缩放画板。**
   - 触屏：在卡片上双指缩放数轴。
   - 放大以后，在数轴上左右拖动可以移动。可拖的点仍然按原来的方式拖。
   - 线下一条细条，显示现在看的是整条线的哪一段。
3. **限度。**
   - 最大放大到一个刻度大约 48 个单位宽，不再放大。
   - 不会多出新的细分：放大只把课程原有的刻度拉开。
   - 最小就是整条数轴（课程原来的范围）。
4. **刻度抽稀。**
   - 任何缩放下，刻度间距不到 6 个单位时，按 1、2、5、10 的倍数只画一部分刻度。
   - 卡片标出的数总保留刻度和数字。
   - 放大后自然回到每个整数一个刻度。
   - 这一条也改变静止时的样子（BT-19 的梳子会变成每 5 个一个），见问题 2。
5. **只是视图。**
   - 不进 schema，模型不知道，不进操作记录，不影响完成判定，恢复课程时不恢复缩放。
   - 放大时拖点，点停的位置和不放大时一样。
6. **卡片高度不变。** 标签行数按整条数轴预留，放大缩小都不改变卡片大小。
7. **讲课和缩放。**
   - 学生缩放就是手动导航，沿用画板已有的手动导航和教学镜头的交接。
   - 教学镜头恢复时，数轴也回到整条。
   - 讲课时动到窗口外的点不会藏起来，因为下一次教学镜头会把整条线带回来。

## 不在这个提议里

**静止时用更紧的窗口**（例如不再总从 0 开始，或把 `MAX_WINDOW` 改小）：
- 好处：不用任何手势就能减少挤；
- 代价：会改变所有现有数轴课的画面，而且是 Coach 的改动，不是 OLL 的。

建议先看缩放的效果，再单独决定。

## 产品负责人的决定（2026-11-25）

1. **滚轮**：指针在数轴卡片上时，滚轮缩放数轴本身；在卡片外照旧缩放画板。
2. **刻度抽稀**：默认就抽稀，静止时也一样。
3. **静止时的窗口**：不改。有了缩放和抽稀，默认范围不再那么重要；从 0 开始也让孩子看到数有多大，改它会改变所有现有数轴课的画面。以后如果课里还挤，再单独提。
