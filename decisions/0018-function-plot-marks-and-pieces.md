# 0018：函数图上的标记与分段函数（AI 课程）

状态：Proposed（待产品负责人确认文末问题）
日期：2026-11-14（数学表现力计划 §7 第 4 步，M1 顺序第一项）

## 背景

- **M1 基线**（Coach #76）：函数图扩展能补全的开放题有 5 道，见下表。
- **探针证据**（M3 第 2 步）：分段函数 f(x) = x + 1（x < 0）、2（x ≥ 0）在两组里都选了函数图，然后失败。常数段 `2` 被拒绝（“必须依赖 x”），修复在两个错误之间来回，4 次调用后没有课。

**卡片和程序今天能做的**（读代码核实）：

- **函数图卡片能画带标签的竖线 / 横线（`guides`）、带标签的点、曲线上的洞。** 示例 quadratic-v2 画了对称轴和顶点，教学观察通过。
- **滑杆能驱动点的坐标和竖线的位置**（`points` 的 x、y，`guides` 的 value 可以绑定表达式）。所以顶点 (h, k)、截距 −c/m 这类标记能跟着滑杆动。
- **标签是固定文字。** 跟着滑杆动的标记，标签不能写数值，否则拖一下就错了。
- **Coach 的视图规划已经在课程演示的每个状态下，用数值方法找出零点、极值、截距、洞和定义域边界**（用于选窗口）。推导大部分已有。
- **没有的**：线段（斜率三角形要用）、只在区间上画的曲线和端点开闭（分段函数要用）、坐标轴上的区间。

| 开放题 | 老师会画的 | 本决定之后 |
|---|---|---|
| G68-26 | 画 y = 2x − 3 的点和直线，加“上升 / 前进”三角形 | 补全（斜率三角形） |
| G68-28 | m、c 的含义：标出截距 c，加斜率三角形 | 补全（截距、斜率三角形） |
| G912-23 | 对称轴竖线 | 补全（对称轴；卡片已有） |
| G912-16 | 坐标轴上标出定义域和值域 | 建议不做（见问题 1） |
| G912-38 | 什么是极限：曲线上的洞，两侧的值逼近同一高度 | 不靠本决定：洞今天已经自动画出，缺的是“两侧逼近”的演示。现有两个采样点在曲线上移动的功能可能已经能做，单独核实 |

分段函数不补全任何开放 M1 题，它是为 M3 加的（探针里失败的那一类）。

## 决定

### 1. 标记：一个节级选项，模型只点名，程序推出、绑定、检查

一个选项 `marks`，列出要画的标记。标记不改变数的含义，所以是选项，不是新配方（0016 的规则只约束数的含义）。

| 标记 | 模型写 | 程序推出并画出 | 滑杆拖动时 | 卡片 |
|---|---|---|---|---|
| 截距 | `intercepts` | 线性和二次函数：用公式写出交点坐标表达式，画点；标签只写“y 截距”“x 截距”，不写数值 | 点跟着走 | 已有 |
| 顶点 / 对称轴 | `vertex`、`symmetry_axis` | 二次函数：顶点表达式和过顶点的竖线；标签写“顶点”“对称轴” | 点和竖线跟着走 | 已有 |
| 斜率三角形 | `slope_triangle` | 用函数图已有的两个采样点画“前进 Δx、上升 Δy”两条线段 | 线段端点跟着采样点走 | **要新增**：可绑定端点的线段 |

- **表达式写不出来时**（不是线性或二次函数）不提供这个标记，在节里拒绝，让节换一个画法（问题 2）。
- **拖动中标记会消失**：例如抛物线抬离 x 轴，横截距不存在。卡片要在这一刻隐藏这个点，而不是画到窗口外或画错（渲染检查的一项）。
- **洞**：视图规划已经自动处理，不在这次范围。

### 2. 分段函数：每段一个公式和区间

| 配方 | 模型写 | 程序推出并画出 | 卡片 |
|---|---|---|---|
| 函数图（已有）加 `pieces` | 每段：公式、区间（左右端点）、端点开闭 | 每段只在区间上画；端点按开闭画空心或实心；检查各段区间不重叠 | **要新增**：区间曲线、端点开闭 |

- **常数段**（`2`）在分段时允许：它只在区间上画，不会被当作整条横线。
- 不分段的函数图仍然拒绝常数公式，规则不变。

### 3. 先渲染，再判定器，再配方（计划 §5）

1. 本仓库先加两样渲染：可绑定端点的线段；区间曲线和端点开闭。再加一项行为：标记不存在时隐藏。都在真实播放器里检查。
2. **判定器**：函数图今天没有（问题 3）。
   - 和数轴判定器一样，每道用例预先写好期望的值（截距坐标、三角形的 Δx 和 Δy、各段端点）。不拿程序自己推出的值去比，否则判定器只是在检查自己。
   - 加反例（画错必须判不通过）。
3. 再写选项和推导。先用真实生成流程测试，再做小试验：对照组和候选组，同样的新用例，每组重复两次。调用次数在试验前报给产品负责人。
4. 与 0017 一起冻结代码，与 Coach #81 一起做一次速度检查（三组，用 `--previous-build` 区分影响）。

## 待确认的问题

1. **范围**：截距、顶点、对称轴、斜率三角形、分段函数。
   - 建议的顺序：先做卡片已有的截距、顶点、对称轴，再做要新渲染的斜率三角形和分段函数。
   - 建议**不做**定义域 / 值域：只有 1 道开放题，却要新渲染（坐标轴区间）加值域推导。
2. **表达式写不出来的标记**：建议在节里拒绝，不画。探针显示，旁白讲没画的东西是最难防的误导。代价是每次多一次调用，频率在小试验里测。
3. **判定器**：同意先写函数图判定器吗？计划 §5 要求先有判定器再写配方，今天没有。
4. **标准**（沿用 0016 问题 2）：
   - 范围内“绝不误导”，范围外“不比今天差”。
   - 已知的范围外近邻：曲线下的面积、切线、多个函数相交、定义域 / 值域。
5. **请求大小**：一个选项（`marks`，三个值）和分段的 schema，估计 400–700 B，**新增特征名零个**。原型做好后实测再实现，2,000 B 余量（Coach #83）能容纳。
