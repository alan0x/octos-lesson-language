# 0013：数轴

状态：Accepted（产品负责人 2026-11-11 确认，四个待确认问题均按建议决定，见文末）
日期：2026-11-11（学科插件计划决定 S16：3–8 年级数学可视化优先，数轴为第一项；表现力计划 B9）

## 背景

OLL 擅长代数、函数、三角和立体，但 3–8 年级最常用的数轴没有对应的卡片。现在只能拼凑：

- 示例 `learner-context-number-line-v2`（“用数轴理解 3+(-5)”）用 `diagram` 的七个方框假装成数轴：没有刻度，没有比例，“向左移动 5 格”无法画出来，只能靠旁白；这张卡片在渲染时还会被截断。
- 用 `geometry` 画一条线加几个点（物理匀速运动的轨道就是这样做的）可以表示位置，但卡片是正方形，大半空白；没有分数刻度、跳跃箭头、空心端点和区间，也不能让学生把点拖到刻度上。

数轴贯穿美国 3–7 年级的标准：分数在数轴上的位置（3.NF.A.2）、整数与有理数的大小和绝对值（6.NS.C.6–7）、有理数加减作为移动（7.NS.A.1）、不等式的解集（6.EE.B.8、7.EE.B.4）。

## 决定

### 1. 新的卡片类型 `number_line`，属于 `math` 插件

```json
{
  "do": "write", "as": "line", "kind": "number_line", "role": "main_visual",
  "content": {
    "title": "从 3 出发，加上 −5",
    "range": {"min": -6, "max": 6},
    "ticks": {"step": 1, "subdivisions": 1, "labels": "every_major", "format": "integer"},
    "points": [
      {"as": "start", "value": 3, "label": "起点"},
      {"as": "end", "value": -2, "label": "终点", "shown": "when_emphasized"}
    ],
    "jumps": [
      {"as": "move", "from": "start", "by": -5, "label": "+(−5)", "hops": true}
    ],
    "intervals": [],
    "bindings": [
      {"target": "move.by", "expression": "change"}
    ]
  }
}
```

- **范围与刻度**：`range` 给出显示范围；`ticks.step` 是主刻度间距，`subdivisions` 把每格再分几份（分母，例如 4 表示四分之一）。`labels` 决定哪些刻度写数（主刻度、全部或不写），`format` 决定写法：整数、小数、分数或带分数。分数写成竖式分数，不写成 `0.25`。刻度太密时 Runtime 自动隐去部分标签，但不改刻度本身；点和跳跃起止所在刻度的数字总是保留（见文末补充）。
- **点**：`value` 是位置，可以是数，也可以是分数字符串 `"3/4"`，Core 把它规范化为精确的分子和分母，避免 `1/3` 变成 0.333…。点可以是实心或空心（`style: "closed" | "open"`），可以有标签，可以 `shown: "when_emphasized"`，到讲的时候才出现。
- **跳跃**：从一个点或一个数出发，向右或向左跳 `by`。画成数轴上方的弧形箭头，箭头上写标签。`hops: true` 时每个单位画一跳（“向左 5 格”能一格一格地数）。终点由 Runtime 算出，不由作者填写，因此不会出现“箭头停在 −1、旁白说 −2”。
- **区间**：两端各自开或闭，也可以向一端无限延伸（`to: null`），用于不等式的解集。
- **绑定**：点的 `value`、跳跃的 `from` 和 `by`、区间的两端都可以绑定课程变量，复用现有的 `bindings`、受限表达式和生成标签（`label.precision`）。`animate` 一个变量，就能看到点移动、箭头一跳一跳地伸长。
- **可寻址部件**：`line#start`、`line#move`、`line#solution` 等，可以强调、指向、连线、聚焦，与其他卡片相同。

### 2. 学生的操作复用已有任务

- 绑定到变量的点可以由学生拖动。拖动时吸附到最近的刻度（含细分刻度），因此“把 3/4 放到数轴上”拖到的就是精确的 3/4。
- 判定复用已有的 `expression_target`：例如变量 `p` 的目标值 0.75。不新增任务类型。
- “标出一个区间”“画一次跳跃”这样的作答留到以后（表现力计划 B2 的新任务类型）。

### 3. 代码在插件包里，第一方插件随 OLL 一起安装

- 节点的 Schema、校验、规范化、headless 归约和 Web 渲染都放在 `packages/plugin-math`，Core 和 Web Runtime 通过一张**第一方插件清单**登记它，不在 Core 里写数轴的代码。
- 第一方插件与 OLL 同包发布（0012 第 2 条），宿主装了 OLL 就装了所有第一方插件，所以这里**不建第三方插件的动态注册机制**。插件节点类型的登记只做到能放下数轴、分数模型这样的节点为止。
- 执行能力 `plugin:math/number-line@1`，对应 `math` 插件 0.2.0。课程使用数轴时 `deriveExecutionRequirements` 报告这个能力；不认识它的旧播放器在播放前明确拒绝（0012 第 5 条）。这是第一个插件执行能力，Octos Learn、学生课程包查看器和课程库从这里开始把已安装的插件传给播放器。

### 4. 版式

数轴卡片是宽而矮的横条（约 560×180 白板单位，按标签和区间的数量增高），不再占一个正方形。字号与现有图形一致，最小可读尺寸由排版检查。

### 5. 第一版不包括

竖直数轴（温度计、海拔）、双数轴（比和比率）、同一张卡片上的多条数轴、对数刻度、学生画跳跃或区间的作答。

## 原因

数轴的教学含义在于“比例正确的刻度”和“移动”：分数刻度要精确，加减是有方向、有步数的跳跃，解集的端点要分开闭。这些用 `diagram` 或 `geometry` 只能近似，而且终点要由作者算，模型算错就和旁白矛盾。把它做成一张由程序计算的卡片，正确性留在程序里（计划原则“Program-owned correctness”），Coach、Studio 和课程包用同一个构建器生成，同一个渲染器播放。

把代码放在 `plugin-math` 而不是 Core，是 0012 的方向；但只做第一方静态登记，是因为这次的目标是尽快给学习者一张新的数学卡片，而不是再做一层基础设施（S16）。

## 补充：隐去标签时保留点的数字（2026-11-11）

Coach 第 4 次速度检查的课里，长数轴的标签每 3 个留一个，终点停在 5 上却没有数字（34 格的线）；19 格的线上终点停在 −7 也一样。学生看得到“终点”，读不出它是几。这是 Runtime 隐去标签的缺陷，Studio 和 CoursePack 的数轴（最长 40 格）同样会遇到，所以在 Runtime 修，不靠 Coach 把线缩短。

- **保留哪些数字**：学生看得见的点，以及跳跃的起点和终点，所在刻度的数字总是画出，随动画和拖动一起移动。
- **只保留本来就有的数字**：按 `labels` 和 `format` 本来就不写数的刻度（例如只写主刻度时的四分之一刻度）仍然不写，“把点拖到 3/4”仍是读刻度的题。
- **隐藏的答案不提前给出**：`shown: "when_emphasized"` 的点，它的值不保留，即使跳跃停在那里。
- **不挤在一起**：隐去标签时，保留数字左右相邻的标签让开（显示“5”，不是“5 6”）；保留的数字比 0 优先。两个保留的数字放不下一行时，第二个放到下一行。
- **点的名称**：两个点的名称会挤在一起时（起点 0、终点 1/4），第二个放到下一行。
- **不在刻度上的点**（变量停在两刻度之间，如 2.6）没有刻度可写，不另加数字。
- **隐去标签的间隔**：按人们数数的间隔隐去（每 2、5、10、20、25、50 个……），不出现每 3 个或每 13 个一标的数轴。
- **会动的数轴版式不变**：点被绑定或可拖动时，卡片按最多需要的行数留位（点的名称每个一行；标签被隐去时，保留的数字每个点一行），拖动和动画中数轴不跳、卡片不变高。
- **已知限制**：`when_emphasized` 的点被强调出现后，在隐去标签的长数轴上仍可能没有数字。Coach 的数轴不用这种点；作者在 Studio 用到时，应让数轴短到标签不被隐去。
